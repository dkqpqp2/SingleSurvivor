# SingleSurvivor — 핵심 게임 루프 설계

**날짜:** 2026-09-14
**상태:** 브레인스토밍 완료, 사용자 검토 대기 (새 대화 세션에서 이어서 진행 예정)

## 배경 및 목표

"뱀파이어 서바이버(Vampire Survivors)"류 게임을 그대로 베끼지 않고 **나만의 방식**으로 비틀어서 Unity 포트폴리오용으로 제작한다. 프로젝트 폴더는 `D:\SingleSurvivor` (기존에 진행 중이던 `D:\Unity\TestMazeTower`의 미로 타워디펜스와는 장르가 달라 별도 Unity 프로젝트로 분리).

이번 스펙은 **핵심 게임 루프**에 집중한다. 업적/칭호 시스템과 그걸 통한 캐릭터 언락 같은 계정 단위 메타 진행 시스템은 핵심 루프가 검증된 뒤 별도 스펙으로 다룬다.

## 원작과의 차별화 포인트 (핵심 아이디어)

일반적인 뱀파이어 서바이버류는 "몬스터를 죽이면 경험치 젬이 나오고, 그게 쌓이면 레벨업 → 무기/스탯 선택" 구조다. 이 프로젝트는 레벨업 트리거 자체를 바꾼다.

1. **몬스터 처치는 레벨업과 무관하다.** 일반 몬스터를 잡아도 즉시 보상이나 경험치가 나오지 않는다 (처치 수 기반 업적/칭호 시스템은 다음 스펙으로 미룸).
2. **시간제 픽업이 레벨업을 트리거한다.** 일정 시간마다 상자/보석 같은 픽업이 **맵 안 랜덤 위치**에 스폰된다. 플레이어가 직접 찾아가서 먹어야 하며, 몬스터 무리 속에 있을 수도 있어 위험을 감수해야 한다.
3. **픽업 하나당 "3개 중 1개 선택" 팝업**이 뜬다. 선택지는 뱀파이어 서바이버처럼 "새 무기 획득"과 "기존 무기/스탯 강화(이동속도, 공격속도 등)"가 섞여서 랜덤으로 나온다.
4. **보스는 플레이어를 쫓아오지 않는다.** 정해진 시간마다 보스가 맵 어딘가(플레이어에게 알려주지 않는 위치)에 스폰되고, 그 자리에 머물며 맵 전체에 닿는 원거리 투사체/장판 공격을 가한다. 플레이어는 공격을 피하면서 보스가 어디 있는지 추측·탐색해서 직접 찾아가 처치해야 한다. 보스를 잡지 않고 무시하는 것도 가능하다(단, 공격은 계속 날아옴).

## 스코프 결정

- **이번 스펙:** 이동, 자동공격(무기), 몬스터 웨이브, 시간제 픽업 → 레벨업 선택 팝업, 보스 헌팅 메커닉, 승패 판정까지의 핵심 루프
- **다음 스펙으로 미루는 것:** 일반 몬스터 처치 기반 업적/칭호 시스템(예: "일반 몬스터 1000마리 처치 → 칭호 '학살자'"), 칭호를 통한 캐릭터 언락, 세이브 데이터, 여러 플레이 캐릭터

## 핵심 결정 사항 정리

| 항목 | 결정 |
|---|---|
| 뷰 | 2D 톱뷰 (Unity 2D 프로젝트, 스프라이트 기반) |
| 비주얼 | 무료 도트(픽셀아트) 에셋을 구해서 적용 (구체적 에셋 팩은 구현 단계에서 선정) |
| 무기/업그레이드 획득 방식 | 뱀서류처럼 새 무기 획득 + 기존 무기·스탯 강화가 한 선택지 풀에 섞여서 3택 1 팝업으로 제공 |
| 일반 몬스터 처치 보상 | 없음 (즉시 보상 없음 — 처치 수는 다음 스펙의 업적 시스템에서 다룸) |
| 픽업 스폰 위치 | 맵 안 랜덤 위치 (플레이어 근처가 아님 — 찾아가야 하고, 몬스터 무리 속 위험 감수) |
| 보스 공격 범위 | 맵 전체에 닿는 원거리 투사체/장판 (보스 위치 무관하게 어디서든 피격 가능) |
| 보스 이동 | 보스는 플레이어를 쫓아오지 않고 스폰된 자리(혹은 제한된 이동)에 머무름 — 정확한 위치는 플레이어가 추측/탐색으로 찾아야 함 |
| 종료 조건 | 정해진 시간(예: 15분) 생존 시 승리, 체력 0이면 패배 |
| 아키텍처 방향 | **ScriptableObject 기반 데이터 주도 설계** (아래 참고) — 사용자가 이 방향에 동의함 |

## 아키텍처 방향: ScriptableObject 기반 데이터 주도 설계

무기, 업그레이드(스탯 강화), 적, 보스를 각각 `WeaponData`, `UpgradeData` 같은 ScriptableObject 애셋으로 정의하고, 런타임 로직은 이 데이터를 읽어 동작하는 범용 컴포넌트(`WeaponInstance`, `EnemyController` 등)로 처리한다.

**장점 (하드코딩 방식 대비):**
- 새 무기나 업그레이드를 추가할 때 코드를 건드리지 않고 에셋만 만들면 됨 — 콘텐츠 확장이 쉬움
- 포트폴리오 코드로서 "확장 가능한 구조"를 보여줄 수 있음
- 실제 뱀서류 게임들이 흔히 쓰는 패턴이라 실무 감각에 가까움

**트레이드오프:** 초반 설계/보일러플레이트에 하드코딩 방식보다 시간이 조금 더 든다. 무기/업그레이드 종류가 아주 적은 첫 프로토타입 기준으로는 다소 과해 보일 수 있지만, 콘텐츠(무기/적/업그레이드)를 늘려나갈 포트폴리오 프로젝트 특성상 이 구조가 낫다고 판단해 채택.

## 추정되는 핵심 시스템 (다음 대화에서 상세 설계 예정)

- **PlayerController**: 이동(WASD/조이스틱), 체력, 스탯(이동속도/공격속도 등) 보유
- **WeaponData / WeaponInstance**: ScriptableObject로 무기 정의(데미지, 공격 패턴, 쿨다운 등), 인스턴스가 실제 발사/타격 처리. 플레이어는 여러 무기를 동시에 보유 가능
- **UpgradeData**: 스탯 강화 정의(이동속도 +X% 등), 레벨업 선택 팝업의 선택지 풀에 무기 획득과 함께 섞여서 등장
- **EnemySpawner / EnemyController**: 시간 경과에 따라 난이도가 올라가는 몬스터 스폰, 플레이어를 추적하는 기본 근접 몬스터
- **PickupSpawner**: 일정 시간마다 맵 랜덤 위치에 픽업(상자/보석) 생성, 플레이어가 접촉하면 레벨업 선택 팝업 트리거
- **LevelUpUI**: 3개 중 1개 선택 팝업 — `WeaponData`/`UpgradeData` 풀에서 랜덤 3개를 뽑아 표시
- **BossController**: 정해진 시간마다 스폰, 플레이어를 추적하지 않고 제자리(혹은 제한적 이동)에서 맵 전체에 닿는 원거리 공격 수행, 체력 보유, 처치 시 소멸
- **GameManager**: 생존 타이머, 승패 판정(시간 종료 시 승리 / 체력 0 시 패배)
- **HUD**: 체력바, 생존 타이머, 보스 등장 경고 표시

## 다음 단계 (새 대화 세션에서)

이 스펙은 브레인스토밍 단계에서 핵심 방향까지만 잡은 상태다. 새 대화를 열어 이 문서를 함께 검토하면서:

1. 각 시스템의 정확한 인터페이스(클래스/필드/메서드)를 확정하고 스펙을 보완
2. 스펙에 대한 최종 승인
3. `superpowers:writing-plans`로 구현 계획(Task 단위) 작성
4. Unity 프로젝트 스캐폴딩(2D 템플릿, git 초기화 등)부터 구현 시작

아직 정해지지 않은 세부 사항(무기 몇 종으로 시작할지, 픽업 스폰 간격, 몬스터 스폰 난이도 곡선, 구체적으로 쓸 무료 도트 에셋 팩 등)은 새 대화에서 계속 다듬는다.
